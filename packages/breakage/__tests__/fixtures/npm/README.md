# npm fixture projects

Each directory is a miniature consumer project: its package source, manifests, Breakage configuration, contracts, and frozen peer environments live together. Local packages keep their own `package.json` beside `src/`. Alternate source files represent deliberate case-specific changes to the same package.

| Project                 | Behavior                                                                                                                                                        |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `candidate-minimatch`   | A host written for Minimatch 8, with complete Minimatch 8 and 9 environments. The default configuration selects 8; the incompatible case selects 9.             |
| `candidate-peer-ranges` | A coordinated host and integration sharing renderer 18. Cases vary declarations, optionality, prerelease versions, or the integration's direct renderer import. |
| `runtime-dependencies`  | A shared host reached through an optional helper package. Cases make the helper required, remove its manifest, or introduce a shadow peer.                      |
| `coupled-peers`         | A representative containing host 1 and renderer 19, with a contract for each relationship.                                                                      |

The [shared project](../../../tests/public/fixtures/npm) supplies the public consumer contracts, released host environments, and a candidate environment template. It lives inside the public restore boundary so released contracts retain all their inputs. Tests can select new labels and versions by cloning these authored environments.

The [fixture harness](../../../tests/public/npm-fixture.ts) copies a whole project, applies a case's changes, compiles each `src/index.ts` to its manifest's `main`, and packs the local packages offline. It preserves bare peer imports. Runtime workspace dependencies become absolute tarball paths only in the disposable copy. Frozen lock files remain authored fixture inputs. Installed `node_modules` trees and authoring `dist` outputs are excluded from copies so every test rebuilds its own source and establishes its own dependency installation.

The Minimatch environments own their exact published dependency pins and npm lock files. The fixture's `test:prepare` script runs `npm ci` to populate its ignored `.cache/` directory, including when dependency trees already exist. Breakage's `test:run` task declares this script as a prerequisite; full, sharded, and watch test runs prepare it automatically. Repository installation and checks do not. Run `pnpm run test:prepare` at the root to dispatch workspace preparation tasks explicitly. Disposable projects include their own copy of the npm cache, then install frozen dependencies offline. Frozen representatives remain outside the pnpm workspace; their own lock files are their only installation authority. These fixed regression environments remain under Renovate's default fixture exclusion.

All npm fixture projects use npm for both frozen environment and candidate installation. Candidate tarballs use [`--legacy-peer-deps`](https://docs.npmjs.com/cli/v11/using-npm/config#legacy-peer-deps) to skip peer resolution entirely: installed candidates must resolve peers from the frozen representative at runtime. This also allows focused exploration outside declared support. Breakage checks declarations and installed peer identity itself. Bun runs the test suite and compiles disposable fixture sources.

Current fixture packages are private workspace members with unique package names, exports, and `workspace:*` development dependencies. The shared [Vite Plus configuration](../../../../../scripts/fixture-tasks.ts) orders upstream builds before fixture builds and uses `vp pack` to emit `dist/index.js` and `dist/index.d.ts` from each package's `src/index.ts`. Package dependencies and peers remain external imports. There are no per-fixture tsconfigs. The root `check:vp` command invokes a Vite Plus validation task that depends on the workspace build, so the task graph finishes those builds before checking every project. The root TypeScript configuration covers fixture sources, configuration, and contracts through actual package declarations, without source aliases or manual dependency links. Optional runtime dependencies that are also needed to compile a fixture are declared as development dependencies so they participate in the build graph. Historical package sources remain outside the workspace and are also checked by the root TypeScript configuration.

Run `pnpm run check:vp` from the repository root to build prerequisites and run Vite Plus linting and type checking across every project. `pnpm run build` also builds all current fixture packages. The Minimatch authoring packages resolve their declared supported peer range through the development workspace; the exact Minimatch 8 and 9 runtime installations still come exclusively from their frozen representatives. Run compatibility tests through the repository test commands so every candidate is rebuilt and executed inside its disposable repository.
